Step 1 — Add AppConfig model to prisma/schema.prisma.

Append the following block at the END of the file, after the existing `AlertConfig` model:

```prisma
// ─── APP CONFIG (Phase 4) ─────────────────────────────────────────────────────
// Generic key/value store for runtime-editable configuration.
// 'alert_email' key holds the global low-stock alert recipient email.
// key is the PK (natural identifier) — no redundant UUID needed.
// D-07: Single global email destination stored here. AlertConfig per-product is NOT used.

model AppConfig {
  key       String   @id
  value     String
  updatedAt DateTime @updatedAt
}
```

Step 2 — Push schema to Neon database:
```bash
npx prisma db push
```

This uses DIRECT_URL from prisma.config.ts for DDL. No migration file is created — db push is the established pattern for this project. Wait for the command to complete successfully before continuing.

Step 3 — Regenerate the Prisma client:
```bash
npx prisma generate
```

This regenerates `src/generated/prisma/` so that `prisma.appConfig` is available in TypeScript. Both steps are REQUIRED — db push updates the database but does NOT update the TypeScript client.

Step 4 — Type-check to confirm client was regenerated correctly:
```bash
npx tsc --noEmit
```

If tsc fails with errors related to `prisma.appConfig`, the generate step was not successful — re-run `npx prisma generate` and check again.
