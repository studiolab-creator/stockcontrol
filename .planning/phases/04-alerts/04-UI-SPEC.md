## Typography

Derived from existing page headings and body text patterns across the app.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px (text-sm) | 400 (regular) | 1.5 |
| Label | 14px (text-sm) | 600 (semibold) | 1.5 |
| Heading (page) | 20px (text-xl) | 600 (semibold) | 1.2 |
| Subheading / card title | 16px (text-base) | 600 (semibold) | 1.2 |

Weights used: 400 (regular) and 600 (semibold) only — 2 weights maximum.

Notes:
- Page headings use `text-xl font-semibold text-foreground` — established pattern from all existing pages (`/dashboard`, `/productos`, current `/alertas` placeholder).
- Muted secondary text uses `text-sm text-muted-foreground` — used for descriptions, empty state body, table secondary values.
- Label visual distinction from Body is achieved via color (`text-foreground` semibold vs `text-muted-foreground` regular), not a separate weight.
- Badge text is 12px (text-xs, font-medium) — baked into `badge.tsx` cva definition.

## Surface Inventory (Phase 4 scope)

### 1. `/alertas` page — full replacement

**Current state:** Placeholder (`"Próximamente"` heading + description paragraph).
**New state:** Two-section ADMIN-only page.

#### Section 1 — Global alert email config (top)

```
Page heading: "Configuración de alertas"   ← text-xl font-semibold text-foreground
Section heading: "Email de notificaciones" ← text-base font-semibold text-foreground
Description: "El email al que se enviará notificación cuando el stock de un producto baje del mínimo."
             ← text-sm text-muted-foreground
```

Layout: `<form>` with vertical stack (`flex flex-col gap-4`).
- `Label` + `Input` (type="email", name="email", placeholder="ej: equipo@empresa.com")
- Input shows pre-filled value if `AppConfig` row exists.
- Primary CTA Button (default variant): "Guardar email"
- Inline field error below input (Zod `.email()` failure): text-sm text-destructive
- Success feedback: `toast.success("Email guardado")` via sonner (established pattern).
- Error feedback: `toast.error("No se pudo guardar. Intentá de nuevo.")` via sonner.

#### Section 2 — Products with active alerts (bottom)

```
Section heading: "Productos con stock bajo activo"  ← text-base font-semibold text-foreground
```

Layout: `Table` (shadcn/ui) — same structure as `/productos` table.

Columns: Nombre | Stock actual | Stock mínimo

- "Stock actual" cell: `{stock}{unidad ? ' ' + unidad : ''}` — numeric value, no badge needed (the presence in this table IS the alert indicator).
- "Stock mínimo" cell: same format.
- `orderBy: { nombre: 'asc' }` — alphabetical.

Empty state (when no `alertActive=true` products):
```
Centered block, py-12:
  text-base font-semibold text-foreground:  "Todo en orden"
  text-sm text-muted-foreground:            "No hay productos con stock bajo actualmente."
```

#### Page-level separator

Use `<Separator />` (shadcn) or `mb-8` gap between Section 1 and Section 2 to visually distinguish configuration from status.

### 2. `/productos` page — Stock column addition

**Current state:** Table columns: Nombre | SKU | Tipo | Categoría | Unidad | Stock mínimo | Acciones
**New state:** Add `Stock` column between `Unidad` and `Stock mínimo`.

Column: **Stock**
- Cell content: `{product.stock}{product.unidad ? ' ' + product.unidad : ''}`
- If `isLowStock` (`product.stock <= product.minStock`): render `<Badge variant="destructive">Stock bajo</Badge>` inline after the number, with `gap-2` between number and badge.
- Layout: `<div className="flex items-center gap-2">` wrapping number + conditional badge.

This is the exact pattern from `DashboardClient` (`isLowStock` helper + `Badge variant="destructive"`), adapted for the table row context. Source: `src/components/dashboard-client.tsx:49` and `src/components/dashboard-client.tsx:112-114`.

No query change needed — `prisma.product.findMany({ include: { categoria: true } })` already returns `stock` and `minStock` (full Product model).

## Interaction Contracts

### Email save flow (`/alertas` Section 1)

1. Input pre-filled with current `AppConfig.value` if row exists; empty string otherwise.
2. User edits email field.
3. Submit button ("Guardar email") is always enabled (validation on server, not client — consistent with existing pattern).
4. On submit: button shows `<Loader2 className="mr-2 h-4 w-4 animate-spin" />` + "Guardando..." while pending.
5. On success (`state === undefined` after submission): `toast.success("Email guardado")`, input retains saved value (page revalidates via `revalidatePath('/alertas')`).
6. On field error (invalid email): inline error text below input — `text-sm text-destructive` — "Ingresá un email válido."
7. On server error: `toast.error("No se pudo guardar. Intentá de nuevo.")`.

### Low-stock badge in `/productos`

1. No interaction — purely presentational.
2. Badge renders if `product.stock <= product.minStock`.
3. No hover state, no click action on badge itself.
4. The row's "Editar" button remains the only action per row.

### Access control

- `/alertas` page: if user is not ADMIN, `requireAdmin()` redirects to `/dashboard` before any content renders.
- No UI element for non-ADMIN users to reach `/alertas` — BottomNav and sidebar both render the "Config. Alertas" link (existing in `app-sidebar.tsx:25`), but server-side redirect handles enforcement.

## Accessibility Contracts

Following patterns already established in existing components:

- Email `Input` must have an associated `Label` (htmlFor/id pairing) — same as all other form fields.
- "Guardar email" button must communicate pending state via `aria-disabled` or `disabled` attribute during submission.
- Empty state text must be visible in the DOM (not CSS-only) — standard pattern.
- `Badge variant="destructive"` in `/productos` table: no additional ARIA needed — the cell also contains the numeric stock value which provides full context.
- Table structure: `TableHeader` + `TableBody` with `TableHead` cells already provides screen reader semantics — no additional ARIA required.
